# DocBro Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fast, native word-processor app for macOS, Windows and Linux that opens and saves Word (`.docx`) and Markdown files, looks and behaves like the "SheetBro Docs" layout mock, and runs a built-in MCP server so AI tools (Claude, Cursor, Codex, …) can read and edit the open document while the user watches and can undo every change. Its Assistant panel is also a chat with Claude that can use the document and any MCP servers the user adds (MCP client + MCP settings). It is SheetBro's sibling for documents.

**Architecture:** Same shell as SheetBro (`../sheetbro`): Tauri 2, a Rust core that owns windows, menus, file I/O and the MCP server (HTTP on 127.0.0.1 + `--mcp-stdio` bridge), and a React + TypeScript frontend. One difference: in SheetBro the workbook model lives in Rust (IronCalc). In DocBro the document lives in the webview's editor (TipTap / ProseMirror), because typing has to stay local and instant. So Rust forwards every MCP `tools/call` to the active window as an `mcp-call` event, the webview runs the tool as one editor transaction (visible live and a single undo step), and answers through the `mcp_reply` command. `.docx` and `.md` conversion runs in TypeScript, next to the editor schema it has to match. The Assistant chat runs in Rust, so the API key never reaches the webview: Rust calls the Anthropic Messages API, connects to the user's MCP servers as a client (stdio and Streamable HTTP), and runs the tool loop; document tools go through the same Rust → webview dispatcher as external clients, so the assistant's edits are one undo step per tool call too. The window UI is a React port of `template/SheetBro Docs.dc.html`; every menu, the command palette and the native menu run commands from one registry (`src/commands.ts`).

**Tech Stack:** Tauri 2, Rust (stable, edition 2021), `tiny_http`, `serde_json`, `dirs`, `getrandom`; React 19, TypeScript, Vite, TipTap 3 (`@tiptap/react`, `@tiptap/starter-kit`, `@tiptap/extension-text-align`, `@tiptap/extension-text-style`, `@tiptap/extension-highlight`, `@tiptap/extension-table`, `@tiptap/extension-image`, `@tiptap/markdown`), `docx` (export), `jszip` (import), `@fontsource/ibm-plex-{sans,serif,mono}`, Vitest + jsdom for TS tests, `cargo test` for Rust; from Task 16 `reqwest` (rustls, streaming) and `futures-util` for the Anthropic API.

**Spec:** None was written; the user skipped the design interview. The spec is the product brief below plus the layout mock `template/SheetBro Docs.dc.html`. Every decision that neither SheetBro's README nor the mock establishes is marked *(call)*, so the user can overrule it while reviewing.

## Product brief

- **Files:** open `.docx` and `.md` (dialog, drag onto window, Finder "Open With"). Save as `.docx`; *Save As…* picks `.docx` or `.md` by extension. New document = empty window. *(call: no `.odt`, `.rtf`, `.txt` in v1; PDF only through the system print dialog)*
- **Editing, the v1 schema:** paragraphs; headings 1–3; blockquote; divider; bold, italic, underline, strikethrough; text color; highlight; alignment left/center/right/justify; bulleted and numbered lists, nested; links; tables (insert, add/remove row and column); images inserted from a file; hard line breaks; comments (Task 13); one-line header and footer with page numbers (Task 14). Nothing else is in the editor, because everything in the editor must survive a `.docx` round trip.
- **Not in v1** *(call)*: real pagination and page setup, footnotes, tracked changes, font family and size pickers (the body font is a view preference, see below), code blocks, collaboration, model providers other than Anthropic, saved chat history (a chat lives until **New** or the window closes).
- **Find & replace** bar (⌘F / ⌘⌥F) *(call: the mock has none, but the MCP tool needs the same engine)*. It slides in under the menu bar.
- **Undo/redo** covers user and AI edits alike; each AI tool call is exactly one undo step.
- **AI tools:** same as SheetBro: off by default, a toggle, a port, a token that can be regenerated, ready-made snippets for Claude Code, Claude Desktop, Cursor, VS Code, Windsurf, Gemini CLI, Codex CLI, and "Other". They live in **MCP settings** (Task 12).
- **Assistant** *(user's decision: the panel is a real chat)*: ask Claude about the document; Claude can call DocBro's own document tools and the tools of any MCP server the user adds (HTTP or stdio). **MCP settings** (opened from the panel) hold the Anthropic API key and model, the list of servers to connect to (with an "Add MCP server" form and a SheetBro preset), and the "Serve DocBro" section above. Tasks 15–17.
- **Windows:** one document per window, cascade, a file lives in one window only, macOS app stays in the Dock with no windows. All ported from SheetBro.

## Global Constraints

- Product name `DocBro`; Cargo package `docbro`, lib `docbro_lib`; npm package `docbro`; bundle identifier `com.jetorbit.docbro`; MCP `serverInfo.name` `"docbro"`, `title` `"DocBro"`.
- MCP default port **7425** (SheetBro uses 7424, so both apps can run at once). The ports allowed are 1024–65535.
- MCP config file: `<config dir>/com.jetorbit.docbro/mcp.json`, mode `0600` on unix, keys `enabled`, `port`, `token`.
- Server is off by default, binds `127.0.0.1` only, requires `Authorization: Bearer <token>`, refuses any request with an `Origin` header or a `Host` other than `127.0.0.1:<port>`/`localhost:<port>`. Behaviour copied from SheetBro's `mcp.rs`.
- MCP protocol versions: `["2025-11-25", "2025-06-18", "2025-03-26", "2024-11-05"]`, tools only.
- Versions follow SheetBro's `package.json` and `Cargo.toml`: `tauri = "2"`, `@tauri-apps/api ^2.12`, React `^19.3`, Vite `^8.3`, TypeScript `^7.0`; TipTap packages all on the same `^3` minor; `vite.config.ts` dev port 1420, strict.
- Package manager: pnpm. Node 20.19+ or 22.12+. macOS 11+ minimum. Bundle targets `["app", "dmg"]`, as in SheetBro.
- License MIT. Fonts come from `@fontsource` (IBM Plex Sans 400/500/600/700, Serif 400/500/600 + italic 400, Mono 400/500); never from Google Fonts at runtime, because the app must work offline.
- Colors, radii, shadows and sizes come from the mock's tokens and values. Use `var(--…)` only; no hex literals in components except the mock's own (`#fff` on accent, `#f3dc6b` highlight swatch).
- **Compact shell (user decision, overrides the mock's sizes; reference screenshot `docs/design/compact-shell-reference.png`, measured against the 52px top bar at about 1.8x):** the in-window menu bar is about 36px tall (buttons 28px tall, 14px font, `0 10px` padding, 2px gap, 13px icons; open dropdown panels `min-width` 240px, rows 32px tall, 13px font, keys 11.5px) and the outline sidebar is 210px wide (rail 40px) with rows about 24px tall (`3px 8px` padding, 13px font, 10px of indent per heading level, 11px `OUTLINE` label), the Words / Characters / Read time stats on one inline row (bold number, then its label), and a compact FILE card about 29px tall (20px icon tile, 12px name). Everything else keeps the mock's values.
- Responsive rules (mock 656–663, 723), exact values: assistant open only if window ≥ 760px, width 320px below 1100px and 380px otherwise; outline shows at ≥ 900px (≥ 1240px with the assistant open); comments rail shows at ≥ 1200px (≥ 1560px with the assistant open); window `minWidth` 640. Focus mode hides menu bar, outline and comments rail.
- Window config: `titleBarStyle: "Overlay"`, `hiddenTitle: true`, `trafficLightPosition: {x: 18, y: 26}`; the top bar is 52px tall.
- Assistant settings: `<config dir>/com.jetorbit.docbro/assistant.json` (`api_key`, `model`) and `servers.json` (the user's MCP servers, including header and env values), both mode `0600` on unix (*call: no OS keychain in v1*). The API key is never sent to the webview (it only learns the last four characters), never logged, and never appears in an error message. Default model `claude-sonnet-5-5`, editable text. Request headers `x-api-key`, `anthropic-version: 2023-06-01`; `max_tokens` 4096.
- Assistant limits: at most 12 model rounds per message; a tool result over 20,000 characters is cut with `… truncated`; connecting to an MCP server times out after 10 s and a tool call after 60 s. Tool names sent to the model are `<serverId>__<tool>`, restricted to `[A-Za-z0-9_-]` and 64 characters.
- Adding a stdio server runs a program the user typed: the add form states the exact command that will run and needs an explicit confirm. A server is never started unless it is switched on.
- UI copy is sentence case and plain English, like SheetBro ("This document has unsaved changes. Close it without saving?").
- Commit messages: conventional (`feat:`, `fix:`, `docs:`, `chore:`), ending with
  `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Opening a Word file with parts DocBro can't keep, then pressing ⌘S.** Footnotes, tracked changes, complex headers/footers, page setup. The user expects not to lose them silently. DocBro shows a banner naming what will be lost, and the first ⌘S on that file asks before overwriting. Tests: Task 4 `reports_parts_it_cannot_keep`, Task 6 `first_save_over_a_lossy_import_needs_confirmation`.
2. **The AI edits while the user is typing.** ⌘Z right after an AI edit must undo exactly that edit: not the user's last words, and not half of the AI edit. Test: Task 10 `each_tool_call_is_one_undo_step_and_never_merges_with_typing`.
3. **`read_document` on a 300-page document.** The tool returns a page of blocks plus a hint for where to continue, not 5 MB of text. Test: Task 10 `read_document_pages_long_documents`.
4. **A tool call with no window open, a window that never answers, or a window closed mid-call.** The client gets a readable tool error within the timeout and never hangs. Tests: Task 11 `call_times_out_with_a_readable_error` and `closing_a_window_fails_its_calls`; the no-window case is the manual check in Task 12, Step 5.
5. **Whitespace and non-ASCII text in a `.docx` round trip.** Leading/trailing spaces, tabs, hard breaks, emoji, accented and Indonesian text all come back unchanged. Test: Task 4 `round_trips_every_supported_node_and_mark` (its fixture carries these).
6. **An MCP server that hangs, floods or returns garbage, and the API key.** A stuck server times out with its name in the error and the window stays responsive; a stdio server that prints log lines on stdout still works; the key never shows up in the webview, in logs or in an error. Tests: Task 15 `a_hung_server_times_out_with_its_name_in_the_error`, `stdio_roundtrip_and_ignores_non_json_lines`; Task 16 `errors_never_contain_the_api_key`.

## Shared names (the contract between tasks)

Doc JSON is TipTap's `JSONContent`. The node and mark names are fixed by `createExtensions()` (Task 2):

- Nodes: `doc`, `paragraph`, `heading` (`level: 1|2|3`), `blockquote`, `horizontalRule`, `bulletList`, `orderedList` (`start: number`), `listItem`, `table`, `tableRow`, `tableHeader`, `tableCell`, `image` (`src: string` data URL, `alt: string|null`), `hardBreak`, `text`.
- Block attr: `textAlign: "left"|"center"|"right"|"justify"|null` on `paragraph` and `heading`.
- Marks: `bold`, `italic`, `underline`, `strike`, `link` (`href`), `textStyle` (`color: "#rrggbb"|null`), `highlight` (`color: "#rrggbb"|null`), and from Task 13 `comment` (`id: string`).
- Document-level data that is not part of the ProseMirror doc, in `src/doc/meta.ts`:
  ```ts
  export interface CommentData { id: string; author: string; date: string /* ISO */; text: string; editing?: boolean }
  export interface DocMeta { comments: CommentData[]; header: string | null; footer: string | null; pageNumbers: boolean }
  export const emptyMeta = (): DocMeta => ({ comments: [], header: null, footer: null, pageNumbers: false })
  ```
- Command ids (snake_case, used by the registry, the native menu and the `menu` event): `new open save save_as print undo redo clear_format find replace select_all focus outline comments assistant dark_mode larger_text sans_font palette table image link divider comment header footer page_numbers text h1 h2 h3 quote ul ol bold italic underline strike highlight color align_left align_center align_right align_justify`.

### Task 3: Export `.docx`

**Files:**
- Create: `src/formats/docx/export.ts`, `src/formats/docx/export.test.ts`, `src/formats/docx/fixture.ts`

**Interfaces:**

- Produces:
  - `exportDocx(doc: JSONContent, meta?: DocMeta): Promise<Uint8Array>`. Built with the `docx` package. `meta` is accepted from now on and ignored until Tasks 13 and 14 give it a mapping.
  - `fixtureDoc(): JSONContent`. Exported from `fixture.ts` and reused by Tasks 4, 6 and 10. It holds one of every node, mark and attr in the shared names (except `comment`), plus the text `"  dua spasi\tlalu tab"`, a `hardBreak`, `"Émoji 🎉 dan kalimat Indonesia: Selamat pagi!"`, a blockquote, a horizontalRule, a 2-level nested bullet list, an ordered list with `start: 3`, a 2×2 table with a header row, and a 1×1 PNG image as a data URL.

Mapping, pinned so the importer (Task 4) can invert it:
- heading N → paragraph style `Heading{N}`; paragraph → `Normal`; `textAlign` → `w:jc` (`left`→`start`, `center`, `right`→`end`, `justify`→`both`; no `jc` when null).

**Interfaces:**

- Produces:
  - `type DroppedPart = "headers" | "footers" | "comments" | "footnotes" | "tracked_changes" | "page_setup" | "other_content"`
  - `interface DocxImport { doc: JSONContent; meta: DocMeta; dropped: DroppedPart[] }` (`meta` is `emptyMeta()` until Tasks 13 and 14)
  - `importDocx(bytes: Uint8Array): Promise<DocxImport>`. It throws `Error("Not a Word document")` when the zip has no `word/document.xml`.

The importer is our own (JSZip + `DOMParser`), not mammoth, because mammoth cannot read alignment or colors, so our own files would lose them on reopen. It inverts Task 3's mapping, and it also reads Word-authored files:
- Paragraph style: resolve `w:pStyle` through `word/styles.xml`, following `w:basedOn`. `Heading1..3` → heading; `Title` → heading 1; `Quote` and `IntenseQuote` → blockquote; `Heading4+` → paragraph; anything else → paragraph. An empty paragraph whose only property is a bottom border → horizontalRule.
- Lists: `w:numPr` (numId, ilvl) → resolve `numFmt` through `numbering.xml` (`abstractNumId`). `bullet` → bulletList, anything else → orderedList with `start` from `w:start`. Consecutive paragraphs with the same numId become one list, and a higher ilvl becomes a nested list.
- `w:highlight` (named) maps to its hex color; `w:shd w:fill` maps to highlight unless it is `auto`.
- Images: `a:blip r:embed` → rels → `word/media/*` → data URL with the MIME type from the file extension.
- `dropped` gets `headers`/`footers` when `[Content_Types].xml` lists header/footer parts, `comments` when `word/comments.xml` exists, `footnotes` when `word/footnotes.xml` has any footnote with an id > 0, `tracked_changes` when `w:ins`/`w:del` appear in the body (the text of `w:ins` is kept, `w:del` is dropped), and `page_setup` when `w:sectPr` has margins or a size other than Letter/A4 defaults. `other_content` covers text boxes, charts, SmartArt and equations (`w:txbxContent`, `c:chart`, `dgm:`, `m:oMath`). The part is skipped and its text is lost. Tasks 13 and 14 narrow `comments`, `headers` and `footers` once DocBro can keep them.
